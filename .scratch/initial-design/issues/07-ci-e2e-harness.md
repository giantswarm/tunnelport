# CI-runnable E2E harness

Status: ready-for-human
Type: HITL

## What to build

Automate the slice-3 smoke test as a CI job that runs on every PR and
on `main`. Spins up kind, installs Teleport (or connects to a cloud
test tenant), provisions sample `TeleportBot`/role/token, deploys the
operator chart from slice 6, applies a sample `RemoteApp`, waits for
`status.ready=true`, runs a curl-pod assertion against the rendered
Service, asserts the response matches the producer app, then tears
down.

The HITL coordination required:

- Decide which Teleport instance backs CI (cloud test tenant credentials
  in CI secrets, or a locally-run Teleport binary started inside the
  CI job).
- Decide CI infrastructure (GitHub Actions vs Tekton — the Giant Swarm
  e2e-testing skill suggests Tekton may be the org default; confirm).
- Decide how the `TeleportBot`/role/token are provisioned each run
  (idempotent script via Teleport API, or pre-provisioned and reused).

Reuses the manifests, runbook, and curl-pod assertion from slice 3 —
this slice is the wrapping that makes them runnable headlessly.

## Acceptance criteria

- [ ] CI job green on a clean main branch
- [ ] CI job red when the smoke flow is intentionally broken (e.g. invalid token Secret)
- [ ] Job runs in under ~10 minutes end-to-end
- [ ] No persistent state between runs — each run provisions and tears down
- [ ] Documented in `hack/smoke/README.md` how to run the same flow locally for debugging
- [ ] Test Teleport credentials stored as CI secrets (not committed)
