# Reconciler renders `Deployment` + `Service` + `ConfigMap` with rolling strategy

Status: done
Type: AFK

## What to build

Controller-runtime reconciler that, given a `RemoteApp`, owns three
rendered objects via `OwnerReferences`:

1. **`ConfigMap`** holding the tbot config (`application-tunnel`,
   `proxy_server: spec.proxyAddr`, `app_name: spec.appName`, listener
   `tcp://0.0.0.0:<spec.port>`, onboarding via static token referenced
   from the mounted Secret).
2. **`Deployment`** with `replicas: spec.replicas || 1`,
   `strategy.rollingUpdate: { maxSurge: 1, maxUnavailable: 0 }`. Pod
   template mounts the tbot ConfigMap and the `tokenRef` Secret, plus an
   `emptyDir` for tbot's destination directory (per ADR 0002). Canonical
   labels set: `tunnelport.giantswarm.io/role=tbot`,
   `tunnelport.giantswarm.io/remoteapp=<name>`. tbot image and resource
   requests/limits from operator Helm values, not from the CR.
3. **`Service`** of type `ClusterIP`, name = CR name, port =
   `spec.port`, selector on the canonical labels.

Spec mutations re-render owned objects. Deleting the CR cascades.
Reconciler does not read the token Secret's contents — only references
it by name in the volume mount.

## Acceptance criteria

- [ ] Applying a `RemoteApp` produces all three resources in the CR's namespace with correct fields
- [ ] All three rendered objects have `OwnerReferences` pointing back to the `RemoteApp`
- [ ] Deleting the `RemoteApp` cascade-deletes all three
- [ ] `spec.port` change updates ConfigMap, Deployment listener, and Service port; Deployment rolls
- [ ] `spec.replicas` change scales the Deployment without rolling
- [ ] `spec.appName` / `spec.proxyAddr` change updates the ConfigMap and rolls the Deployment
- [ ] Unit tests exercise each rendering path

### Agent Brief

**Category:** enhancement
**Summary:** Implement the controller-runtime reconciler that materializes a `RemoteApp` into three owned objects (`ConfigMap`, `Deployment`, `Service`).

**Current behavior:**
The `RemoteApp` CRD exists but nothing reacts to it. Applying a CR has no effect beyond storing the resource.

**Desired behavior:**
Applying a `RemoteApp` produces a `ConfigMap`, `Deployment`, and
`Service` in the same namespace as the CR. All three carry
`OwnerReferences` pointing back to the `RemoteApp` so that deleting the
CR cascade-deletes them. Spec mutations re-render the owned objects;
field-by-field semantics are listed in the issue body. The reconciler
**must not** read the contents of the `tokenRef` Secret — only reference
it by name in the pod's volume mount.

**Key interfaces:**
- **tbot config in ConfigMap**: mode `application-tunnel`,
  `proxy_server: spec.proxyAddr`, `app_name: spec.appName`, listener
  `tcp://0.0.0.0:<spec.port>`, onboarding via `token` join method using
  the Secret referenced by `spec.tokenRef`.
- **Deployment pod template**: mounts the ConfigMap and the token Secret
  as projected volumes; mounts an `emptyDir` for tbot's destination
  directory (per ADR 0002 — do not introduce a PVC or `StatefulSet`);
  tbot container image and resource requests/limits come from the
  operator's Helm values, not from the CR; canonical labels set on the
  pod template:
  - `tunnelport.giantswarm.io/role=tbot`
  - `tunnelport.giantswarm.io/remoteapp=<cr-name>`
- **Deployment strategy**: `RollingUpdate` with `maxSurge: 1` and
  `maxUnavailable: 0` — guarantees no zero-pod window for new
  connections during a roll.
- **Service**: `ClusterIP` only, selector matches the canonical labels,
  port = `spec.port`. Service name = CR name (no override field on the
  CR — rejected during design).

**Acceptance criteria:**
- [ ] Applying a `RemoteApp` produces all three resources in the CR's namespace with correct fields
- [ ] All three rendered objects have `OwnerReferences` pointing back to the `RemoteApp`
- [ ] Deleting the `RemoteApp` cascade-deletes all three
- [ ] Spec mutations propagate as documented (port → ConfigMap + Deployment + Service; replicas → scale only; appName/proxyAddr → ConfigMap + Deployment roll)
- [ ] Unit tests exercise each rendering path

**Out of scope:**
- Status field population — slice 4.
- Watch on the `tokenRef` Secret and auto-roll on rotation — slice 5.
- Helm chart and RBAC packaging — slice 6.
- Reading pod logs anywhere in the reconciler — forbidden by ADR 0003.
